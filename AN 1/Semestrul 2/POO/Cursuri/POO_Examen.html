Sinteză pentru examenul de Programare Orientată pe Obiecte (C++). Acoperă toate capitolele din curs și răspunde la întrebările de teorie de tip „descrieți pe scurt…”. Folosește caseta La examen pentru baremul tipic.

1 Introducere în POO & principii

Programarea Orientată pe Obiecte (POO) este o paradigmă care organizează codul în jurul obiectelor (date + operații), nu în jurul funcțiilor (ca în programarea procedurală).

Cele 4 principii fundamentale

PrincipiuDescriere
AbstractizareReținem doar caracteristicile esențiale ale unei entități, ignorând detaliile irelevante. Clasa = model abstract.
ÎncapsulareDatele și metodele care le prelucrează sunt grupate într-o clasă; accesul la date este controlat (private/protected/public). Ascunderea implementării (information hiding).
MoștenireO clasă derivată preia membrii unei clase de bază și o poate extinde/specializa. Reutilizare de cod.
PolimorfismAceeași interfață, comportamente diferite. La compilare (supraîncărcare funcții/operatori, template) și la execuție (funcții virtuale, RTTI).

Clasă vs. obiect

  • Clasă = tip de date definit de utilizator (un „șablon”). Nu ocupă memorie pentru date până nu se instanțiază.
  • Obiect (instanță) = o variabilă concretă de tipul clasei; are stare proprie (valorile câmpurilor).
  • Interfață = setul de operații publice prin care lucrăm cu obiectul.

De reținut

C++ este un limbaj multi-paradigmă: suportă atât programare procedurală (ca C), cât și POO și generică (template). Nu obligă la POO.

2 Recapitulare C & noutăți C++

Transferul parametrilor

ModSintaxăEfect
Prin valoarevoid f(int x)Se copiază argumentul; modificările NU se văd afară.
Prin pointervoid f(int *x)Se transmite adresa; *x modifică originalul.
Prin referințăvoid f(int &x)Alias al argumentului; modificările se văd. Fără */& la apel.

Tipul referință

  • O referință este un alias (alt nume) pentru o variabilă existentă.
  • Trebuie inițializată la declarare și nu poate fi „re-legată” la altă variabilă.
  • Folosită la: parametri (evită copierea), valori întoarse, membri (se inițializează în lista constructorului).
  • Referințele independente ca membri ai unei clase trebuie inițializate în lista de inițializare a fiecărui constructor.
int a = 5;
int &r = a;   // r este alias pentru a
r = 10;       // a devine 10

Supraîncărcarea funcțiilor (polimorfism la compilare)

  • Mai multe funcții cu același nume, dar liste de parametri diferite (număr/tip/ordine).
  • Tipul returnat NU contează pentru diferențiere.
  • Compilatorul alege funcția potrivită după argumentele de la apel; dacă există mai multe potriviri la fel de bune → ambiguitate (eroare).

Argumente implicite (default)

  • Se dau de la dreapta la stânga: void f(int a, int b=2, int c=3);
  • Pot crea ambiguitate cu supraîncărcarea: f() și f(int=1) sunt ambigue la apelul f().

La examen — alocare dinamică

new alocă pe heap și apelează constructorul; delete apelează destructorul și eliberează. new[] ↔ delete[]. La eșec, new aruncă excepția bad_alloc (din <new>). În C se folosea malloc/free care NU apelează constructori/destructori.

3 Clase, obiecte, încapsulare

Structura unei clase

class Cont {
  private:               // implicit la class
    double sold;          // câmp (date membru)
  public:
    Cont(double s = 0); // constructor
    void depune(double v); // metodă
    double getSold() const;
};

Modificatori de acces

struct vs. class vs. union

  • struct = class cu membri impliciti public; la class sunt impliciti private.
  • union: toți membrii ocupă aceeași zonă de memorie (doar unul activ). Poate avea metode și constructori, dar NU funcții virtuale și NU moștenire.
  • Union anonimă: membrii se accesează direct, fără nume de union.

Pointerul this

  • Pointer implicit, disponibil în orice metodă nestatică, ce indică spre obiectul curent.
  • Tipul: Clasa* const (în metodă const: const Clasa* const).
  • Folosit pentru: dezambiguizare nume, întoarcerea lui *this (înlănțuire obj.f().g()).

Funcții & clase friend

  • O funcție/clasă friend are acces la membrii private/protected ai clasei care o declară prietenă.
  • Prietenia nu se moștenește și nu este reciprocă (dacă A e prietenă cu B, B nu e automat prietenă cu A).
  • O funcție friend nu are pointer this (nu e membră), primește obiectul ca parametru.

Funcții inline

  • Sugestie pentru compilator de a înlocui apelul cu corpul funcției (evită overhead-ul apelului).
  • Metodele definite în interiorul clasei sunt implicit inline.
  • Este doar o recomandare; compilatorul poate ignora.

4 Constructori, destructori, copy-constructor

Constructorul

  • Același nume cu clasa, fără tip returnat (nici măcar void).
  • Apelat automat la crearea obiectului; inițializează starea.
  • Poate fi supraîncărcat; poate avea argumente implicite.
  • Dacă nu definim niciun constructor, compilatorul generează unul implicit (fără parametri). Dacă definim ORICE constructor, cel implicit NU mai e generat automat.
  • Lista de inițializare: Clasa(int i) : camp(i), baza(...) {} — obligatorie pentru membri const, referințe, obiecte fără constructor implicit și clase de bază cu parametri.

Capcană frecventă (examen)

Dacă o clasă are constructor cls(int i=1) ȘI constructorul implicit cls(), la new cls[10] apare ambiguitate — compilatorul nu știe pe care să-l apeleze fără argumente. Fix: elimini unul dintre ei.

Destructorul

  • ~Clasa() — fără parametri, fără tip, nu poate fi supraîncărcat (unul singur).
  • Apelat automat la distrugerea obiectului (ieșire din scop / delete).
  • Rol: eliberează resurse (memorie, fișiere). Ordinea: invers față de construire.

Ordinea construire / distrugere

  1. Clasele de bază (în ordinea declarării moștenirii).
  2. Membrii (subobiectele), în ordinea declarării în clasă (nu în lista de inițializare).
  3. Corpul constructorului.

Destrucția se face în ordine strict inversă.

Constructorul de copiere (copy-constructor)

La examen — întrebare de teorie tipică

Sintaxă: Clasa(const Clasa &other); — primește o referință constantă la un obiect de același tip.

Când e apelat: (1) la inițializarea unui obiect din altul: Clasa b = a;; (2) la transmiterea prin valoare a unui obiect ca parametru; (3) la întoarcerea prin valoare a unui obiect dintr-o funcție.

De ce parametru referință? Dacă ar fi prin valoare, ar trebui copiat → ar apela copy-constructorul → recursie infinită.

Motivație (de ce îl definim noi): când clasa gestionează resurse (pointeri, memorie dinamică), copierea implicită („shallow copy”, bit cu bit) copiază doar adresa → două obiecte indică aceeași zonă → double free / efecte laterale. Definim un copy-constructor cu copiere profundă (deep copy).
D(const D &s) : B(s) {
    d = new int;     // alocă memorie nouă
    *d = *(s.d);        // copiază valoarea (deep copy)
}

Regula celor 3 (Rule of Three)

Dacă o clasă are nevoie de destructor, atunci probabil are nevoie și de copy-constructor ȘI de operator= definite de programator.

Membri statici inițializați; obiecte statice

Obiectele statice locale se construiesc o singură dată (la prima trecere) și se distrug la sfârșitul programului (destructori statici, în ordine inversă).

5 Supraîncărcarea operatorilor

Permite ca operatorii (+ - * == [] () << ++ …) să funcționeze pe obiectele clasei.

Membru vs. friend

Funcție membruFuncție friend / liberă
Operand stângobiectul curent (this)primul parametru
Nr. parametri (binar)1 (operandul drept)2
Necesar pt. <<,>>nu se poate (op. stâng e ostream)da

Reguli importante

  • NU se pot supraîncărca: .   ::   ?:   .*   sizeof   typeid.
  • NU se pot crea operatori noi și NU se schimbă aritatea sau precedența.
  • =, [], (), -> trebuie să fie funcții membru.
  • La argumente implicite: nu se pot da valori implicite, excepție operator().

Prefix vs. postfix (++ / --)

T& operator++();      // prefix:  ++a  (întoarce referință)
T  operator++(int);   // postfix: a++  (param int fictiv, întoarce copia veche)

Alți operatori uzuali

  • operator[] — indexare; întoarce de obicei o referință (pentru a permite atribuire a[i]=x).
  • operator() — „functor”; obiectul devine apelabil ca o funcție.
  • operator-> — „smart pointer”; trebuie să întoarcă un pointer sau un obiect cu ->.
  • operator new / operator delete — controlul alocării.
  • operator= — atribuire; verifică auto-atribuirea (if(this!=&o)) și întoarce *this.

Moștenire & operatori

Toți operatorii (mai puțin operator=) se moștenesc. operator= NU se moștenește — fiecare clasă are propriul comportament de atribuire.

6 const, static & conversii

const cu pointeri

La examen — „pointeri cu const”

Citește de la dreapta la stânga față de *:

int *const p2 = &a;   // *p2=9 OK;    p2=&b EROARE

Funcții membru const

  • int get() const { ... } — promite că nu modifică starea obiectului (this e const).
  • Doar metodele const pot fi apelate pe obiecte const.
  • Excepție: membrii marcați mutable pot fi modificați și din metode const.
  • Obiectele temporare sunt tratate ca const.

Membri const și referință

  • Trebuie inițializați obligatoriu în lista de inițializare a constructorului (nu prin atribuire în corp).

Capcană (examen)

const int y; ... A(int i){ y = -i+3; } → eroare: câmpul const nu poate fi modificat prin atribuire. Fix: A(int i): y(-i+3) {}.

Membri statici

  • Variabilă statică = comună tuturor obiectelor (o singură copie pentru clasă). Trebuie definită în afara clasei: int A::x = 5;
  • Metodă statică: static int f(); — aparține clasei, nu unui obiect.

Metode statice vs. nestatice (teorie examen)

Conversii între tipuri

  • Constructor cu un parametru = conversie implicită de la tipul parametrului la clasă (ex. SimpleClass(int) permite push_back(5)). Se blochează cu explicit.
  • Operator de cast: operator Tip() const; — conversie de la clasă la alt tip.
  • De la derivată la bază: conversie implicită. De la supraclasă la componentă: trebuie scrisă explicit (operator cast).

7 Tratarea excepțiilor

La examen — barem

Sintaxă + cum se alege blocul catch + fără conversie de tip + mecanism + catch(...) + aruncare din funcții.

Sintaxă

try {
    if (eroare) throw valoare;  // aruncă o excepție (orice tip)
}
catch (int e)      { /* tratează excepții int */ }
catch (const char* m){ /* tratează șiruri */ }
catch (...)        { /* prinde orice (trebuie ultimul) */ }

Proprietăți & mecanism

  • La throw, execuția părăsește imediat blocul try și caută primul catch compatibil.
  • Blocul catch se alege după tipul expresiei aruncate — primul care se potrivește, în ordinea scrierii. NU se face conversie de tip (ex. int aruncat nu intră în catch(double)); excepție: conversia derivată → bază.
  • catch(...) prinde orice tip; se pune ultimul.
  • La căutare se face „stack unwinding”: se distrug obiectele locale (se apelează destructorii) între throw și catch — nu sunt apeluri de funcții normale.
  • Excepțiile se pot propaga din funcții apelate; dacă nicio funcție nu prinde excepția → terminate().
  • Excepții standard: bad_alloc (new), out_of_range, etc., derivate din std::exception.

8 Moștenire & compunere

Controlul accesului la clasa de bază

Moștenirepublic bazăprotected bazăprivate bază
publicpublicprotectedinaccesibil
protectedprotectedprotectedinaccesibil
privateprivateprivateinaccesibil

Membrii private ai bazei nu sunt accesibili direct în derivată (dar există în obiect).

Constructori, destructori & moștenire

  • La construire: întâi baza, apoi derivata. La distrugere: invers.
  • Constructorul derivatei apelează constructorul bazei prin lista de inițializare: Derived(int j): Base(j) {}. Dacă nu, se apelează constructorul fără parametri al bazei.

Capcană (examen)

Derived(int j){ x = j; } unde Base are doar Base(int i=10) cu valoare implicită — compilează (apelează Base() implicit cu i=10). DAR dacă baza NU are constructor fără parametri (sau cu toate implicite) → eroare.

Redefinirea (ascunderea) membrilor

Capcană clasică — name hiding

Dacă derivata redefinește f(), ea ascunde TOATE supraîncărcările lui f din bază (ex. f(string)). Apelul d.f(s) dă eroare. Fix: using Base::f; sau redefinești toate variantele, sau apelezi d.Base::f(s).

Compunere vs. moștenire (teorie examen)

La examen — barem (5×0.1)

  • Compunere („has-a”): clasa conține obiecte ale altei clase ca membri.
  • Moștenire („is-a”): clasa derivă dintr-o clasă de bază.
  • Subcomponentele / bazele se creează prin lista de inițializare a constructorului.
  • Drepturi de acces: la subcomponente accesăm doar membrii publici; la bază accesăm publici și protected.
  • Conversie: derivată → bază implicită; supraclasă → componentă doar explicit (supraîncărcare operator cast).

9 Funcții virtuale, polimorfism, clase abstracte

Pointeri & referințe către clase derivate

  • Un pointer de tip bază poate indica un obiect derivat (upcast implicit). Invers — NU fără cast explicit.
  • Capcană: D *p = new B; → eroare (un B nu e un D).

Funcții virtuale

La examen — folosirea lui virtual

  • O funcție virtual permite legare târzie (late binding): prin pointer/referință de tip bază către un obiect derivat, se apelează versiunea din clasa reală a obiectului (decizie la execuție).
  • Fără virtual → legare timpurie (se apelează versiunea după tipul pointerului).
  • Mecanism: vtable (tabel de pointeri la funcții) + vptr în fiecare obiect. Stă la baza RTTI.
  • O funcție rămâne virtuală în toate derivatele, chiar fără cuvântul virtual.
class B { public: virtual void f(){ cout<<"B"; } };
class D:public B{ public: void f(){ cout<<"D"; } };
B *p = new D; p->f();   // afișează "D" (virtual)

Clase abstracte & funcții virtuale pure

  • Funcție virtuală pură: virtual void f() = 0; — fără implementare (obligă derivatele să o definească).
  • O clasă cu cel puțin o funcție virtuală pură este abstractă: NU se pot crea obiecte din ea (doar pointeri/referințe).

Destructor virtual

La examen — destructor virtual (pur)

  • De ce: dacă ștergi un obiect derivat printr-un pointer de bază (delete pBaza;) și destructorul bazei NU e virtual → se apelează doar destructorul bazei → resurse nealiberate (memory leak).
  • Soluție: virtual ~Baza(); → se apelează lanțul corect de destructori (derivat → bază).
  • Destructor virtual pur: virtual ~Baza() = 0; — face clasa abstractă, DAR trebuie totuși să-i dai o implementare (corp), pentru că destructorii derivatelor îl apelează mereu.

Capcană — supraîncărcare vs. suprascriere

Dacă în derivată schimbi semnătura (ex. void Print(B*) în loc de void Print(A*) din bază), NU e suprascriere virtuală — e o funcție nouă care o ascunde pe cea din bază.

10 Moștenire multiplă & virtuală (problema rombului)

Moștenire multiplă

O clasă poate deriva din mai multe baze: class C: public A, public B {};. Ordinea constructorilor urmează ordinea din lista de moștenire.

Problema rombului (diamond)

La examen

Dacă D1 și D2 derivă din B, iar MM derivă din D1 și D2 → MM conține două copii ale lui B → ambiguitate la accesul membrilor lui B.

Soluție: moștenire virtuală — class D1: virtual public B și class D2: virtual public B. Astfel MM are o singură instanță comună a lui B. Trebuie virtual pe ambele ramuri.
class B { ... };
class D1: virtual public B { ... };
class D2: virtual public B { ... };
class MM: public D1, public D2 { ... }; // o singură copie a lui B

La moștenire virtuală, constructorul clasei cel mai derivate (MM) este responsabil de inițializarea bazei virtuale B.

11 RTTI — identificarea tipului la execuție

RTTI (Run-Time Type Identification) permite aflarea tipului real al unui obiect în timpul execuției. Funcționează pentru tipuri polimorfice (cu cel puțin o funcție virtuală).

typeid

La examen — operatorul typeid

  • Necesită #include <typeinfo>; întoarce un const type_info&.
  • typeid(obj).name() — numele tipului; typeid(a)==typeid(b) — compară tipuri.
  • Pe un pointer/referință de bază către obiect derivat polimorfic, typeid(*p) dă tipul real (derivat). Pe tip nepolimorfic dă tipul static.
  • NU se poate supraîncărca.

dynamic_cast

  • D* p = dynamic_cast<D*>(pBaza); — conversie sigură în jos (downcast).
  • Dacă obiectul real nu e de tipul cerut: întoarce nullptr (pentru pointeri) sau aruncă bad_cast (pentru referințe).
  • Necesită ca tipul de bază să fie polimorfic (funcție virtuală).

Comparativ: static_cast nu verifică la execuție; dynamic_cast da.

12 Template — funcții & clase generice

La examen — clase template (barem 5×0.1)

Sintaxă pe clase; toate metodele sunt template; pot exista tipuri implicite (default); servesc la clase parametrizate / reutilizare de cod; exemplu clar.

Funcție template

template<class T>
T maxim(T a, T b){ return a>b ? a : b; }
// maxim(3,5) -> int ; maxim(2.1,9.4) -> double
  • Compilatorul generează automat o versiune pentru fiecare tip folosit (instanțiere).
  • O funcție obișnuită (non-template) potrivită este preferată față de instanțierea unui template.

Clasă template

template<class T, int N = 10>   // poate avea tip implicit
class Stiva {
    T elem[N]; int varf;
  public:
    void push(T x);
    T pop();
};
// definirea metodei în afara clasei:
template<class T, int N>
void Stiva<T,N>::push(T x){ elem[varf++] = x; }

Stiva<int> s;          // N=10 implicit
Stiva<double, 100> s2;

Particularități

  • Parametrii pot fi tipuri (class T) sau valori (int N).
  • Specializare: implementare specială pentru un tip anume — template<> class Stiva<bool> { ... };.
  • Clase template derivate: o clasă template poate moșteni dintr-o altă clasă template.
  • Tot codul template stă de regulă în header (instanțiere la compilare).

14 Șabloane de proiectare (Design Patterns)

Soluții reutilizabile pentru probleme frecvente de proiectare. Clasificare: creaționale, structurale, comportamentale.

Singleton

La examen — clasă cu nr. limitat de obiecte

Pentru „o clasă cu cel mult N obiecte”: constructor privat + metodă statică de creare + contor/alocare dinamică controlată. Singleton = cazul N=1.
class Singleton {
    static Singleton* inst;
    Singleton() {}              // constructor PRIVAT
  public:
    static Singleton* getInstance(){
        if (!inst) inst = new Singleton();
        return inst;
    }
};
Singleton* Singleton::inst = nullptr;

Idee pentru „cel mult 3 obiecte”: contor static; metoda statică de creare întoarce un obiect nou doar dacă contor < 3, altfel nullptr. Constructor privat ca să nu se poată crea direct.

Abstract Factory

Oferă o interfață pentru a crea familii de obiecte înrudite fără a specifica clasele concrete (decuplare). Folosește clase de bază abstracte și funcții virtuale.

★ Strategie pentru problemele „ce afișează / compilează?”

Structura examenului (2025): 1 punct din oficiu + 18 probleme × 0.5p, 2 ore. Alternanță între cod (compilează? ce afișează? o singură modificare de reparare) și teorie.

  1. Caută erorile de compilare clasice: D* p = new B;; const modificat prin atribuire; membru const/referință neinițializat în listă; ambiguitate constructor la new T[]; name hiding (apel la supraîncărcare ascunsă); tip return incompatibil; metodă cu semnătură schimbată care nu mai e virtuală.
  2. Dacă compilează: urmărește cu atenție virtual (legare târzie vs. timpurie), ordinea constructori/destructori (bază→derivat, membri în ordinea declarării), static (valoare comună), prefix/postfix, copy-constructor la trecere/întoarcere prin valoare.
  3. La new T[n]: doar elementele inițializate explicit au valoarea pusă; restul au valoarea din constructorul implicit.
  4. Indică numărul liniei și o singură modificare la întrebările de reparare.
  5. La teorie: răspunde structurat pe punctele din barem (sintaxă, proprietăți, particularități, exemplu).

Pattern recurent

Programe ce afișează din constructor/destructor ("C"/"D") — testează ordinea și numărul de apeluri (mai ales la vector și la moștenire). Numără atent copy-constructorii.
