Programare Orientată pe Obiecte

Sinteză teorie + set de întrebări grilă — FMI București 2025–2026

Ce este POO?

O paradigmă de programare care dictează cum se reprezintă datele și cum se prelucrează. Influențează felul în care sunt gândiți algoritmii.

Limbajele OO populare: Java, Python, C++, C#, Ruby. Limbaje non-OO: Go, Julia, Rust (nu sunt strict OO).

Principiile fundamentale ale POO

ÎncapsulareaContopirea datelor cu metodele de prelucrare în clase; ascunderea informației; localizare mai bună a erorilor
MoștenireaExtinderea unei clase prin adăugarea de noi funcționalități; reutilizare de cod; relație "is-a"
PolimorfismulO metodă poate avea implementări diferite la niveluri diferite ale ierarhiei; la compilare (overloading) și la execuție (virtual)

Versiuni C++

  • C++11 – initializer lists, rvalue references, lambda, nullptr, moving constructors
  • C++14 – generic lambdas, auto, variable templates

Supraîncărcarea funcțiilor (Function Overloading)

Utilizarea mai multor funcții cu același nume. Identificarea se face prin numărul și tipul parametrilor — tipul de întoarcere nu este suficient.

La compilare: transformate în nume unic prin name mangling.

Ambiguități:
  • int f(int) și float f(int) → EROARE (diferă doar tipul returnat)
  • void f(int *p) și void f(int p[]) → EROARE (*p identic cu p[])
  • void f(int x) și void f(int& x) → EROARE ambiguitate
  • Conversii implicite pot genera ambiguitate (ex: myfunc(10) cu float și double versiuni)

Funcții cu valori implicite

  • Parametrii cu valori implicite trebuie să fie la sfârșitul listei
  • Valorile implicite se specifică o singură dată, de obicei în prototip
  • Atenție la ambiguități la supraîncărcare cu valori implicite
void f(int a, int b = 12);  // b are valoare implicita
f(1);      // echivalent cu f(1, 12)
f(1, 20);  // b = 20

Tipul referință

O referință este un pointer implicit — un alt nume (alias) al unui obiect.

  • Trebuie inițializată la declarare (excepție: membri de clasă, parametri, valori returnate)
  • Referințele nule sunt interzise
  • Nu se poate obține adresa unei referințe (&ref dă adresa variabilei referite)
  • Nu se pot crea tablouri de referințe (dar se poate cu std::reference_wrapper)
  • Intern sunt tot pointeri, dar mai siguri
Diferență față de pointer: Incrementarea unui pointer trece la alt obiect de același tip; incrementarea referinței incrementează valoarea referită. 
int a = 20;
int& ref = a;  // ref este alias pentru a
ref++;         // modifica a (a devine 21)

Transmiterea parametrilor

ModSintaxăEfect
Prin valoarevoid f(int x)Copie; modificările nu afectează originalul
Prin pointervoid f(int* x)Adresa originalului; modificările afectează originalul
Prin referințăvoid f(int& x)Alias; modificările afectează originalul; fără overhead de copiere

Alocare dinamică în C++

  • new și delete sunt operatori, nu funcții
  • new alocă și inițializează; delete eliberează
  • La eroare se aruncă excepția bad_alloc din <new>
  • Pentru array: new[] și delete[] (obligatoriu pereche)
  • Alternativă la eroare fără excepție: new(nothrow)
int *pi = new int;       // alocare
delete pi;               // eliberare
int *arr = new int[10];  // vector
delete[] arr;            // OBLIGATORIU []
Memory leak: Dacă nu se face delete, zona rămâne ocupată pe toată durata programului.

mutable

Permite modificarea unui câmp al clasei chiar și dintr-o funcție membră const. Util pentru câmpuri "de caching" care nu afectează starea logică a obiectului.

class Z {
  mutable int j;  // se poate modifica in functii const
public:
  void f() const { j++; }  // OK
};

Cap 2: Clase, Obiecte, Încapsulare

Structura unei clase

class NumeClasa {
  // private implicit
  int dataMembru;
public:
  void metodaPublica();
protected:
  void metodaProtejata();
};
  • Default în class: private
  • Default în struct: public
  • Default în union: public
  • Operatorul :: (scope resolution) pentru definirea metodelor în afara clasei
  • Nu se poate inițializa un câmp nestatic la declarare (se face în constructor)

struct vs class vs union

Union: Nu poate moșteni, nu poate fi moștenită, nu are funcții virtuale, nu are variabile statice de instanță.

Funcții prieten (friend)

O funcție prieten are acces la câmpurile private și protected ale clasei, dar nu are pointerul this.

  • Folositoare la supraîncărcarea operatorilor, funcții de I/O
  • O clasă poate fi declarată prieten: toate metodele ei au acces la privat
  • Relația friend nu este tranzitivă sau simetrică
class MyClass {
  int a, b;
public:
  friend int sum(MyClass x);  // functie friend
};
int sum(MyClass x) { return x.a + x.b; }  // acces la privat

Funcții inline

Sugestie/cerere pentru compilator de a substitui apelul cu corpul funcției. Elimină overhead-ul de apel.

  • Explicit: cuvânt cheie inline
  • Implicit: funcții definite în corpul clasei sunt inline automat
  • Nu funcționează bine cu funcțiile virtuale (ne trebuie adresa pentru vtable)

Pointerul this

  • Fiecare funcție membră ne-statică are implicit pointerul this
  • Pointează către obiectul curent care a apelat funcția
  • Funcțiile prieten nu au this
  • Funcțiile statice nu au this
  • Util la: returnarea obiectului curent, distincție câmpuri/parametri cu același nume
A(int x) { this->x = x; }  // this->x = camp, x = param

Cap 3: Constructori & Destructori

Caracteristici generale

  • Numele = numele clasei; destructorul are prefix ~
  • Nu au tip de întoarcere (nici măcar void)
  • Nu pot fi moșteniți (până în C++11; din C++11 se poate cu using)
  • Nu se pot crea pointeri la constructor/destructor
  • Constructorii pot fi supraîncărcați; destructorul este unic și fără parametri

Tipuri de constructori

TipDefinițieObservații
Default (fără param)A() { ... }Apelat pentru obiecte neînițializate și array-uri dinamice
ParametrizatA(int x) { ... }Poate genera conversii implicite cu un parametru
De copiereA(const A& o)Apelat la inițializare, apel prin valoare, returnare din funcție
Cu valori impliciteA(int x=0, float y=0)Poate ține loc de constructor default

Orice clasă are implicit (dacă nu definim)

  1. Constructor de inițializare (default)
  2. Constructor de copiere (copiere bit-cu-bit)
  3. Destructor
  4. Operator de atribuire =
Problemă la alocare dinamică: Constructorul de copiere implicit face copiere superficială (shallow copy) — ambele obiecte vor pointa spre același bloc de memorie. La distrugere: double free! Soluție: redefinim constructorul de copiere cu deep copy.

Constructorul de copiere — când se apelează?

  • Inițializare explicită: MyClass B = A; sau MyClass B(A);
  • Apel de funcție cu obiect ca parametru prin valoare
  • Returnare din funcție a unui obiect prin valoare
Operator = între obiecte existente nu apelează constructorul de copiere, ci operatorul de atribuire!
classname(const classname& o) {
  // deep copy
}

Lista de inițializare a constructorilor

Obligatorie pentru: referințe, câmpuri const, sub-obiecte fără constructor default, apelul constructorului din clasa de bază.

class Proiector : public Dispozitiv {
public:
  Proiector(int nr) : Dispozitiv(nr) { }  // apel constructor baza
};

class Fred {
  const int size;
public:
  Fred(int sz) : size(sz) {}  // const necesita lista de initializare
};

Ordinea apelării constructorilor/destructorilor

  1. Constructorii claselor de bază (în ordinea moștenirii)
  2. Constructorii membrilor clasei (în ordinea declarării în clasă)
  3. Constructorul propriu

Destructorii în ordine inversă. Obiectele globale se construiesc înaintea celor locale.

Dacă un parametru este transmis prin referință, nu se apelează constructorul de copiere la intrarea în funcție.

Membrii statici ai clasei

  • Există o singură copie pentru toate obiectele clasei
  • Variabilele statice trebuie definite și inițializate în afara clasei: int A::i = 1;
  • Funcțiile statice nu au this și pot referi doar membrii statici direct
  • Se accesează: Clasa::membru sau obiect.membru
class A {
  static int count;
public:
  static int getCount() { return count; }
};
int A::count = 0;  // definire si initializare in afara clasei

Cap 4: Supraîncărcarea Operatorilor

Principii

  • Majoritate operatorilor pot fi supraîncărcați
  • Nu se poate redefini precedența operatorilor
  • Nu se poate redefini numărul de operanzi
  • Nu se pot supraîncărca: ., ::, .*, ?:, sizeof, typeid, alignof

Funcții operator ca membri ai clasei

ret-type ClassName::operator#(arg-list) { ... }
// Exemplu:
loc loc::operator+(loc op2) {
  loc temp;
  temp.longitude = longitude + op2.longitude;  // this implicit
  return temp;
}
  • Pentru operatori binari: un singur argument (obiectul din stânga apelează, cel din dreapta e argument)
  • Prefix ++: operator++() — fără argument
  • Postfix ++: operator++(int) — cu parametru int "dummy"

Funcții operator ca funcții prieten

  • Nu are this → ambii operanzi ca parametri
  • Avantaj: permite 100 + ob (int pe stânga)
  • Pentru ++/-- unari prieten → parametru referință (altfel modificăm copia)
Operatori care NU pot fi prieten: =, (), [], -> 
friend loc operator+(loc op1, loc op2);  // ambii operanzi
friend loc operator++(loc& op);           // referinta pt unari

Supraîncărcarea new și delete

  • Se poate face la nivel de clasă sau global
  • La new supraîncărcat: constructorul se apelează automat
  • La delete supraîncărcat: destructorul se apelează automat
  • Pentru array-uri: operator new[] și operator delete[]

Supraîncărcarea [], ()

  • [] poate întoarce referință → poate apărea la stânga atribuirii (ob[1] = 25)
  • () permite număr arbitrar de parametri → obiecte funcționale (functori)

Spaceship operator (C++20)

<=> supraîncarcă toți operatorii de comparație simultan. Cu = default compilatorul generează automat toți operatorii de comparație pe baza câmpurilor clasei.

Cap 5: Moștenirea în C++

Concepte fundamentale

  • Clasa de bază = superclasă = clasă părinte
  • Clasa derivată = subclasă = clasă copil
  • Agregare (compunere): relație "has-a" — un obiect conține alt obiect
  • Moștenire: relație "is-a" — o clasă este un tip al altei clase
class Derivata : [modificator_acces] Baza { ... };

Modificatori de acces la moștenire

Moștenirepublic din bazăprotected din bazăprivate din bază
publicpublicprotectedinaccesibil
protectedprotectedprotectedinaccesibil
privateprivateprivateinaccesibil
Membrii private din clasa de bază sunt întotdeauna inaccesibili direct în clasa derivată, indiferent de tipul moștenirii.

Moștenire private

  • E mai bine să se folosească compunerea în loc de moștenire privată
  • Nu mai avem relație "is-a" pentru obiect tratat extern
  • Se poate restaura accesul public: using Baza::numeMembru;

Redefinirea funcțiilor membre

2 modalități:

  1. Cu același antet ("redefining" / "overriding" pt virtuale)
  2. Cu schimbarea listei de argumente sau tipului returnat
Important: La redefinirea oricărei funcții din clasa de bază, toate celelalte versiuni (supraîncărcări) ale acelei funcții sunt automat ascunse în clasa derivată!

Schimbarea semnăturii/tipului returnat = schimbarea interfeței = contravine polimorfismului.

Funcții care nu se moștenesc automat

  • Constructorii (se redefinesc noi constructori pentru derivată)
  • Destructorii
  • Operatorul =

Din C++11, constructorii se pot moșteni explicit cu using Baza::Baza;.

Compatibilitate și conversii

Există compatibilitate numai pentru moștenire publică, în sensul derivată → bază (upcasting — sigur):

  • Obiect derivat → obiect bază
  • Pointer/referință la derivat → pointer/referință la bază

Downcasting (bază → derivată) este periculos; se face cu dynamic_cast.

Moștenire multiplă

C++ suportă moștenire multiplă (puține alte limbaje o au). Problemă majoră: problema diamantului.

class Baza { public: int i; };
class D1 : public Baza { };
class D2 : public Baza { };
class D3 : public D1, public D2 { };
// D3 are DOUA copii ale lui i → ambiguitate

Moștenire virtuală — rezolvare

class D1 : virtual public Baza { };
class D2 : virtual public Baza { };
class D3 : public D1, public D2 { };
// Acum D3 are o singura copie a lui i

Cap 6: Funcții Virtuale & Polimorfism la Execuție

Early binding vs Late binding

Early bindingLate binding (virtual)
CândLa compilareLa execuție (runtime)
Bazat peTipul variabileiTipul real al obiectului
PerformanțăMai rapidăMai lentă (dereferențiere ptr)
SintaxăImplicitCuvânt cheie virtual

Mecanismul virtual (vtable / vptr)

  • Fiecare clasă cu funcții virtuale are o vtable — tabelă de pointeri la funcțiile virtuale
  • Fiecare obiect din acea clasă conține un vptr — pointer la vtable-ul clasei sale
  • vptr este inițializat în constructor
  • La apelul unei funcții virtuale: obiect → vptr → vtable → funcție
  • De aceea clasele cu funcții virtuale sunt mai mari cu sizeof(void*)
Cost: Funcțiile virtuale nu pot fi inline (ne trebuie adresa funcției). Folosiți doar când aveți nevoie de polimorfism.

Funcții virtuale pure și clase abstracte

virtual int functie(int i) = 0;  // virtuala pura
  • Clasă abstractă = cel puțin o funcție virtuală pură
  • Nu se pot instanția obiecte de tip abstract (eroare la compilare)
  • Se pot crea pointeri și referințe la clasa abstractă
  • Dacă clasa derivată nu definește funcția pură, ea devine și ea abstractă
  • Utilitate importantă: prevenirea object slicing

Constructori și virtualizare

NU putem avea constructori virtuali.
  • Apelul unei funcții virtuale din constructor/destructor folosește versiunea locală (early binding), nu cea din derivată
  • De ce? La momentul constructorului bazei, obiectul derivat nu e complet construit, vptr-ul local e cel al bazei
  • Alternativă: pattern factory, funcții de clonare (virtual constructor pattern)

Destructori virtuali

Dacă facem upcasting (pointer de tip bază la obiect derivat) și obiectul are memorie alocată dinamic, destructorul trebuie să fie virtual — altfel se apelează doar destructorul bazei, memory leak pentru parte derivată! 
class Baza {
public:
  virtual ~Baza() {}  // OBLIGATORIU daca derivata aloca memorie
};
Base2* p = new Derived2;
delete p;  // fara virtual: apeleaza doar ~Baza()
           // cu virtual: apeleaza ~Derived2() apoi ~Baza()

Regula: Dacă o clasă are funcții virtuale, declarați destructorul virtual.

Excepție: destructor protected și non-virtual — când nu dorim instanțierea directă.

Upcasting și Downcasting

  • Upcasting (derivat → bază): sigur, implicit
  • Downcasting (bază → derivat): periculos, explicit
  • dynamic_cast<Derivat*>(ptr): sigur, întoarce nullptr dacă eșuează, necesită vtable (funcții virtuale)
  • static_cast<Derivat*>(ptr): fără verificare runtime, mai rapid dar periculos

Object slicing

Când un obiect derivat este copiat prin valoare într-o variabilă de tip bază, parte derivată se "taie". Funcțiile virtuale nu mai funcționează corect.

void describe(Pet p) { ... }  // parametru prin VALOARE
describe(dog);  // dog devine Pet, informatia specifica se pierde!

Soluție: transmiteți prin referință sau pointer, sau folosiți clase abstracte.

cuvântul cheie override (C++11)

Previne greșeli la redefinirea funcțiilor virtuale (ex: schimbare accidentală de semnătură). Dacă funcția nu există în bază, eroare de compilare.

void play(note) const override { ... }  // garanteaza ca suprascrie

Cap 7: Tratarea Excepțiilor

Structura try-catch-throw

try {
  // cod care poate arunca exceptii
  throw TipExceptie("mesaj");
}
catch (TipExceptie& e) {  // prinde prin referinta
  // gestionare eroare
}
catch (...) {  // prinde orice exceptie
  // handler generic
}
  • Dacă se face throw și nu există try corespunzător → programul se termină prin terminate()
  • Dacă nu există catch potrivit → terminate()
  • terminate() poate fi redefinit

Ierarhia de excepții standard

Toate excepțiile standard moștenesc din std::exception.

  • std::logic_error — erori logice (argument invalid, out of range)
  • std::runtime_error — erori la execuție (overflow, underflow)
  • std::bad_alloc — eșec la new
Ordinea catch-urilor contează! Puneți catch-ul pe tipul derivat PRIMUL, apoi pe tipul de bază. Altfel catch-ul de bază prinde tot și cel de derivat nu se execută niciodată.

Bune practici

  • Prindeți prin referință const (catch(const std::exception& e))
  • Nu prindeți prin valoare → riscați object slicing
  • Aruncați excepții în constructori dacă obiectul ar fi invalid
  • Fiecare modul ar trebui să aibă o ierarhie proprie derivată (indirect) din std::exception
  • Re-aruncare: throw; fără argument → re-aruncă excepția curentă fără copiere
  • noexcept / noexcept(false) — specifică dacă o funcție aruncă excepții

Când să folosim excepții?

  • Când alternativa cu coduri de eroare este mai complicată
  • Când avem separare clară între "happy path" și "bad path"
  • În constructori (altfel avem obiecte invalide)
  • Nu când locul erorii e aproape de catch (mai simplu cu coduri de eroare)

Tipuri de containere

TipExempleCaracteristici
Secvențialevector, list, dequeOrdine liniară, acces secvențial sau aleator
Asociativeset, map, multiset, multimapRegăsire eficientă după cheie; ordonate (arbore BST)
Neordonateunordered_map, unordered_setHash table; O(1) mediu; nu păstrează ordinea

vector

  • Array dinamic; elemente stocate secvențial în memorie continuă
  • Acces O(1) la orice poziție prin []
  • Adăugare/ștergere O(1) la final (push_back, pop_back)
  • Inserare/ștergere la mijloc: O(n)
  • Funcții: push_back, pop_back, insert, erase, size, resize, clear, empty, begin, end

list

  • Listă dublu înlănțuită
  • Inserare/ștergere O(1) pe orice poziție (dacă ai iteratorul)
  • Nu are acces aleator prin []
  • Funcții extra față de vector: push_front, pop_front, sort, merge, reverse, remove

map

  • Dicționar ordonat: perechi cheie → valoare; chei unice
  • Implementat cu arbore BST balansat; O(log n) la căutare/inserare
  • operator[]: inserează dacă cheia nu există
  • find: întoarce iterator sau end() dacă nu există
  • multimap: permite chei duplicate
  • unordered_map: hash table, O(1) mediu, nu menține ordinea

Iteratori

  • Obiect care gestionează o poziție în container
  • Suportă: ++, --, * (dereferențiere), ==, !=
  • Adaptoarele de containere (stack, queue, priority_queue) nu oferă iterator
  • Tipuri: input, output, forward, bidirectional, random access, reverse
vector<int>::iterator it;
for(it = v.begin(); it != v.end(); it++)
  cout << *it;
